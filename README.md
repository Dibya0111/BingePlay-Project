# BingePlay-Project

BingePlay is a SQL-driven streaming analytics project built with Python and MySQL. The project analyzes users, subscriptions, shows, ratings, and watch-session data to answer business questions around revenue, engagement, content performance, upgrades, binge behavior, and churn signals.

## Project Overview

The analysis connects a Python Jupyter Notebook to a MySQL database named bingeplay using SQLAlchemy and PyMySQL. SQL queries are executed from the notebook and the results are loaded into Pandas DataFrames for inspection.

The database contains the following tables:

users

subscriptions

shows

ratings

watch_sessions

## Questions Analyzed

The notebook answers 12 business-oriented questions:

Active Revenue — active subscription count and total subscription income by plan.

Signup Momentum — monthly signup trends.

Device Analytics — sessions, average watch time, completed sessions, and completion rate by platform.

Rating Distribution — distribution of 1–5 star ratings and the percentage of 4- or 5-star ratings.

Originals vs Acquired — comparison of BingePlay Originals and acquired shows using average IMDb rating and release year.

Binge Day Detection — identification of binge days and the user with the most binge days in Q2 2024.

Q1 Signups Who Never Watched — identification of Q1 2024 signups with no watch sessions.

Over-paying Premium/Family Users — Premium/Family users whose watch history only requires Basic-tier content.

Upgrade Success Cohort — users who started on Basic and later upgraded, including average time from signup to upgrade.

Cliffhanger Comebacks — users returning to an unfinished show within seven days, including the show with the most comeback events.

Consecutive-week Engagement — users with at least four consecutive weeks of engagement and the longest observed streak.

Churn Signal Detection — users whose watch time dropped by at least 50% from May to June 2024.

## Database Setup

The notebook expects a MySQL database called bingeplay.

Create a local .env file in the project directory:

DB_USER=root
DB_PASSWORD=your_password
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=bingeplay

The notebook reads these values using python-dotenv, so database credentials do not need to be stored directly in the notebook.

Important: Never commit your .env file or database passwords to GitHub.
